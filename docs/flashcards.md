# 字卡排程與複習

沿用已安裝的 ts-fsrs 5.x 記憶模型，不重新訓練參數或改寫既有到期日。每個人、每組卡片可設定 80–97% 目標記憶率（預設 90%），於下次評分生效；較高目標會增加複習負擔，並不保證實際正確率。用卡片 ID 與複習次數固定 fuzz 種子，使同一狀態的間隔預覽與提交一致。

## 選卡

- 已到期的 Learning／Relearning 優先，其次依估計可回想率由低至高、遺忘次數與到期日排序。未到期的長期卡不提前進入智慧複習。
- 每四張到期卡穿插一張新卡。每次選卡以 40 張作為到期卡與新卡的合計工作量預算：到期卡仍全部保留，新卡取每日剩餘額度與 `40 - 到期張數` 的較小值。這是可解釋的負擔管理規則，不是訓練所得的最佳值。
- 每日額度以 UTC+8 午夜切換，計算首次排程複習落在當日的不同卡片；同一張新卡再複習不會釋出額度。`review_log.scheduled` 保留舊版依序瀏覽曾影響排程的歷史；新版隨機練習及依序瀏覽只留練習紀錄。
- 考試日以 UTC+8 解讀，長間隔提前至考前一天（距離考試不足一天時至少間隔一小時，且不超過考試日）。預覽與實際評分用同一限制。考前建議新卡數僅供參考，不自動提高每日上限。
- 弱項模式可主動加強尚未到期的已學卡，會影響排程；已刪除的卡片不進入佇列。

## 複習操作

可選 10／20／50／全部張數。先回想再揭曉，以「忘記／困難／記得／熟悉」評分；題目階段不渲染答案。智慧複習、弱項模式的短期學習步驟均依 FSRS due 等待，包含 Good 後仍在 Learning 的卡片；不再把 Again 無條件插到三張之後。等待時可先結束，下次接續伺服器排程。進度計算不同卡片的初次作答，統計另列總評分次數，避免重學讓分母一直膨脹。

長答案在卡片內捲動，卡片移出時禁止互動；尊重 reduced motion。快捷鍵忽略長按、組合鍵、輸入框與揭曉前評分。儲存期間及揭曉前拒絕評分；IndexedDB 完成交易後才換卡，寫入失敗保留卡片並提示重試。

## 同步與一致性

IndexedDB 的 read-modify-write 使用單一 readwrite transaction，送出完成後只移除已確認的 review ID，避免與新評分互相覆蓋。進入下一輪前先嘗試同步，仍未送出的評分會在本機套用於選卡狀態與新卡額度。內容讀取仍需通過線上身分及群組權限檢查。

尚未同步的作答按登入帳號隔離；換帳號時不顯示、套用或送出前一人的紀錄。送出附上原作答帳號，伺服器拒絕已切換登入身分的請求；失敗保留原紀錄。已登入的頁面會定時重試暫時失敗的同步，手機全螢幕複習也會顯示等待同步狀態。

舊版本未保存帳號的作答保留在本機，不能自動歸給目前帳號。頁面提供「恢復先前紀錄」入口，原作答者確認帳號後才原子移入自己的佇列；取消或儲存失敗不刪除舊紀錄。

伺服器以 review ID 去重；較舊的離線事件只補紀錄，不倒退最新記憶狀態。同時來自不同分頁的評分，以 reps／last_review 作為樂觀鎖，將紀錄與狀態寫入同一 D1 batch；衝突時重新讀取、重新計算。`scheduled` 與個人記憶率由 migration 0007 增加，不刪除既有學習資料。

## AI 生成字卡：先評估詞彙、只做英→中（2026-11-09）

`create_deck` 必須附 `vocabulary_plan`（`vocabulary-plan/v1`，`src/shared/vocabulary.ts`）：chatbot 先讀章節重點整理、上傳教材與 IB 文件，列出本章重要詞彙，每個詞註明 core／supporting、重要的理由與大綱編號。伺服器檢查：每張卡都在計畫裡、每個 core 詞彙都有卡、正面是英文詞彙、背面有中文、沒有正面重複，也沒有中→英的反向卡（學生在複習畫面用「正反面對調」反向練習）。計畫存在 `deck_vocabulary_plans`。`add_cards` 同樣拒絕反向卡；字卡組有計畫時，新詞要放進 `vocabulary_additions`。網頁 Prompt 產生器的「雙向單字卡」改成「英→中詞彙卡」。
