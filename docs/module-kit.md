# 互動模組元件庫

目的：讓 chatbot 用預先設計的元件組裝互動模組，而不是每次重寫整頁 HTML、CSS 與腳本樣板。這樣視覺與動態和網站一致，輸出 token 較少，也能讓課堂依學生的操作調整路徑。chatbot 讀到的完整規格是 `get_module_kit` 的回傳，來源在 `src/shared/module-kit-guide.ts`。

## 運作方式

1. chatbot 呼叫 `get_module_kit`，之後用 `<sk-*>` 標記組裝模組，領域計算寫在最後的 `<script>`（`StudyKit.compute / plot / render`）。官方 simulation、diagram、game、visualization3d 的生成 prompt 也被附上精簡版指引，所以 chatbot 在回答那些回合時直接看得到。
2. 課堂載入互動頁時，`lib/utils/iframe.ts`（由 `patch-classroom.mjs` 修改）發現頁面使用 `<sk-` 或 `StudyKit`，就把 `src/shared/module-kit.ts` 的 CSS 與 JS 注入 `<head>`。沒用元件庫的舊模組不受影響。
3. 元件把學習行為用 `postMessage({source:"study-kit"})` 回報。`lib/study-classroom/adaptive.ts` 驗證寄件者是頁面自己的 iframe、限速後，用 `kit-events.ts` 轉成路由訊號。

模組仍在沙盒 iframe 內執行（無 `allow-same-origin`），元件庫不使用網路、`eval` 或 `localStorage`，測試會檢查這點。

## 章節流程

每一章由 chatbot 依 `CHAPTER_FLOW`（`src/shared/module-kit-guide.ts`）生成，播放器依場景標題分流：

1. `先測：章名`：每章 5 到 6 題，基礎（`__d1`）、核心（`__d2`）、難題（`__d3`）三個難度都要有，見下方「前測與教學順序」。
2. 先測（含難題）全對 → `章名〔精簡〕`：不重新教，先一頁重點回顧（公式、適用條件、符號單位），再放考試陷阱提醒與難題練習＋解析，之後仍進檢核。
3. 其他 → `章名`：講解 → 操作 → 紀錄與自我檢核。所有公式、觀念與推理都先講解再實作。
4. `檢核：章名` 是覆核。
5. 覆核沒通過 → `章名〔補強〕`：小步驟重教、加強練習，最後一頁「復測」用全新題目；播放器再讓學生做一次覆核。
6. 全部完成 → 最後一個沒有標籤的場景 `課後：字卡與模考`，邀請學生到 App 的字卡頁（`/decks`）複習英文術語，再到模擬試題頁（`/exams`）模考。chatbot 生成時先找或建立對應牌組與試卷，場景寫出實際名稱。

## 互動規則

- 滑桿不是預設控制項：先想真實實驗怎麼動手；連續量或滑桿確實最清楚時可以用，不設數量硬上限，但不把「幾個滑桿加讀值」當成模擬實驗。
- 科學：操作內建的虛擬器材（見下一節）。chatbot 只寫 `<sk-lab><sk-item kind="…">`，不畫 SVG、不寫拖曳與物理。學生用 `sk-record` 把讀數記進實驗表（`manual` 欄位要自己讀刻度，與真值差超過 `tol` 判讀不準；每欄可設合理範圍，超出標 ✗ 並以 `answer` 事件回報迷思），再用 `sk-numeric`／`sk-choice` 檢核由紀錄算出的結果。
- 數學：不做實驗，講解後直接做題（`sk-numeric`、`sk-choice`、`sk-order`、`sk-match`），一題一個 `sk-tab`。

## 題型

非實驗的科學互動不再只有選擇題。同一章要求至少 3 種不同題型：

| 題型 | 元件 | 操作 |
|---|---|---|
| 分類（放置物品） | `sk-sort`＋`sk-bucket`＋`sk-card` | 拖曳卡片進分類，或點卡片再點分類 |
| 配對 | `sk-match`＋`sk-pair` | 點左邊再點右邊，已配對兩側出現相同編號 |
| 排序 | `sk-order`＋`sk-item` | 拖曳列、點一列再點目標列，或 ↑↓ 按鈕 |
| 圖解標示 | `sk-label`＋`sk-term`＋`<svg data-part>` | 把名稱拖到圖上的編號圓點 |
| 點選部位 | `sk-pick`＋`<svg data-part>` | 點圖上的部位，可單選或多選 |
| 填空 | `sk-fill`＋`sk-text`＋`sk-blank` | 把詞庫的詞拖或點進空格 |
| 配平化學式 | `sk-balance` | 調整係數，兩邊各元素原子數即時顯示 ✓／✗；要最簡整數比 |
| 調數值 | `sk-knob`＋`sk-tune` | 旋轉旋鈕（或 −／＋、方向鍵）調變因，即時顯示結果，要調到目標值 |
| 數值、單選與複選 | `sk-numeric`、`sk-choice` | 既有 |
| 座標圖作答 | `sk-graph` | `points`：點格線交點標點（再點一次移除，或「加一個點」後用方向鍵）；`line`：拖曳兩個控制點，或點控制點再點新位置，讓直線符合斜率與截距 |
| 完成表格 | `sk-table`＋`sk-tr` | 格子用 `|` 分隔，`[答案]` 變成輸入框；數字依 `tolerance`，文字不分大小寫 |
| 點出文字片段 | `sk-mark`＋`sk-hit`／`sk-miss` | 點選文字裡該選的片段（找錯誤步驟、證據、詞性）；多選或漏選都不算對 |
| 自我解釋 | `sk-reflect`＋`sk-point` | 先寫下自己的說明，再對照參考說法逐項勾選重點；文字只留在頁面上，不送出 |

不計分的練習：`sk-flashcards`＋`sk-flash`（術語字卡：先回想、翻面、選「記得」或「還不熟」，不熟的排到最後再出現）。

### 帶著做與「看解答」（2026-11-16）

- `<sk-steps gated>`：每個 `sk-step` 放一小題，答對（或看過解答）才能按下一步，用來做「例題示範 → 帶著做 → 獨立做」中間那一段。
- 同一題答錯兩次，回饋框會出現「看解答」：顯示正解與該題的 `sk-explain`，把題目標成完成，並以 `hint`（`level: 3`）回報，路由會把它算成一次提示。學生不會卡在一題上出不去。`sk-reflect` 本來就會顯示參考說法，不提供這個按鈕。模組草稿預檢會提醒沒有 `sk-explain` 的題目。
- 修正後再答對，回饋是「答對了，修正得很好。」
- 修正一個既有的版面錯誤：答錯的回饋框被同名的計數徽章樣式（`.sk-no`）限制成 22px 高、12px 字，超過一行的回饋會溢出框外。現在回饋框依內容長高。
- 回饋框的 ✓／✗ 改成用筆畫出來的勾與叉（2026-11-17）。
- 修正另一個既有錯誤（2026-11-17）：有滑鼠的裝置把游標移到深色的主要按鈕（例如「檢查答案」）上時，按鈕背景會變成白色而文字仍是白色，看不到字。
- 瀏覽器測試：`node integrations/openmaic/cloudflare/test/module-kit-more.browser.mjs`（需要 Playwright 的 Chromium；可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定），在 1100×900 與 375×667 實際操作每個新元件，並確認手機寬度沒有橫向捲動。

所有題型都以同一個 `answer` 事件回報對錯與 `misconception`，也納入 `sk-progress`。拖曳都有「點選再點目標」的替代，觸控目標至少 44px。

## 虛擬器材（`src/shared/module-lab.ts`）

只在頁面含 `<sk-lab>` 時才注入（約 80 KB，不佔 chatbot 的輸出 token）。桌面是 360×224 的 SVG 實驗桌，器材拖曳、點選替代按鈕、物理與動畫都內建；讀值自動發佈為 `器材id.讀值名`，可給 `sk-record`、`sk-observe` 使用。

| 類別 | kind |
|---|---|
| 化學／通用 | `beaker`、`flask`、`cylinder`、`testtube`（裝液體，可倒液、放固體）、`burette`（滴定管＋放大鏡）、`pipette`、`bottle`（滴瓶／指示劑）、`balance`、`thermometer`、`heater`（可「時間 ×10」）、`stopwatch`、`phmeter`（含探頭）、`solid`、`mass` |
| 物理 | `spring`（虎克定律，阻尼振盪）、`pendulum`、`ramp`（斜面＋小車＋兩個光閘）、`circuit`（接線、節點電壓法求解，燈泡亮度、電表、過載後果）、`optics`（薄透鏡公式，像隨對焦模糊） |
| 生物 | `microscope`（×4／×10／×40、對焦模糊、比例尺、玻片位移；洋蔥表皮與口腔上皮細胞） |

化學模型：強酸、強鹼與弱酸（CH₃COOH）在混合後以電荷平衡解 pH，指示劑顏色（酚酞、甲基橙、溴瑞香草酚藍）由 pH 內插，所以滴定終點附近一滴就會變色。

### 講解與指示

講到要學生動手的句子，chatbot 要在這句 speech 前放 `widget_highlight`（目標在別的分頁或步驟時，模組會先自動切過去再指；沒開的 `<details>` 也會先打開）（target 是 CSS selector）。模組用聚光燈（四周變暗）、雷射點與「換你操作」標籤標示目標，學生操作後自動消失並回報 `operate`；播放器的講解列也同步顯示「換你操作」（沒有指示動作時，以句子中的操作動詞判斷）。投影片則要求每句講到的元素都先 `spotlight` 或 `laser`。器材的子目標 selector 見 `POINTING_RULES`。

### 提問與討論

討論面板不再重複老師的講解（講解只在下方講解列）。學生可以提問（AI 老師即時回答），或按「找虛擬同學討論」啟動虛擬同學討論；兩者都呼叫課堂 AI，所以需要先在該課堂啟用 AI。

## 設計語言

- 與 STUDY 主程式（`src/web/styles.css`、`ui.tsx`）同一套 token：背景 `#fafafa`、卡片白色 90%、hairline 邊線 slate-900/6%、墨色 `#0f172a`、主色漸層 `#0a0a0a→#3f3f46`（深色模式反相）。深色模式依系統偏好切換。
- 光影：soft／lift／glow 三層陰影、卡片頂部高光、主要按鈕頂部 15% 白色高光、背景頂部淡光暈。
- 字體 Geist／Inter／Noto Sans TC，標題用 Fraunces／Noto Serif TC，正文 16px、行高 1.7；圓角：按鈕 16px、卡片 24px（手機 20px）；手機單欄；觸控目標至少 40px。
- 正確與錯誤同時用符號與文字，不只靠顏色。focus 外框清楚，狀態用 `aria-live` 唸出。

## 題目手感

所有題型共用同一套回饋，而不是各寫各的：

- **選項**：自訂圓形／方形指示（選中時內圈長出來），檢查後在列尾出現 ✓／✗ 徽章；答錯的選項輕搖一次。答錯後改選另一個選項，就直接清掉錯誤狀態，不用先按「再試一次」（仍會回報一次 `retry`）。
- **回饋框**：圖示加文字（不只靠顏色）；答對時圖示彈出並有一圈淡淡的擴散，答錯時整張題卡輕搖，題卡邊框跟著變色，學生一開始操作就恢復。
- **按鈕**：答對後檢查鈕變成「✓ 已完成」。數值題按 Enter 就檢查，輸入框依對錯變色。
- **拖放**：拖曳時卡片微微放大傾斜，目標區塊亮起；點選卡片後所有可放入的區塊變成虛線；放下後卡片從放手處滑進新位置（沒放進任何區塊就滑回原位）。空的分類區顯示「放到這裡」。
- **排序**：列的重排用位移動畫（FLIP）滑動，檢查後每一列標示對錯。
- **配對、標示、填空、配平、旋鈕**：新配對的編號彈出、圖上圓點填入時彈出、填空與係數變動有輕彈、旋鈕指針有過渡（拖曳時不延遲）。
- **全部完成**：頁面有兩題以上，全部答對時底部浮出一個「✓ 這一頁的題目全部完成」，2.6 秒後收起。
- 偏好減少動態時，位移、搖動、彈出與滑動全部關閉，狀態仍立即顯示。

## 重來按鈕

排序、配對、分類、標示、點選、填空、配平題各有一顆安靜的「重來」鈕（答對後隱藏）；選擇題答錯後出現「再試一次」。按下時箭頭轉一圈，題目回到起始狀態、清掉對錯標示（排序與分類用滑動回位）。實驗桌的「重設實驗桌」會洗掉整個桌面，所以要按兩次：第一次變成紅色的「再按一次確認」，2.6 秒內再按才重設；離開按鈕或逾時就取消。重設後實驗桌淡入重建。元件是 `StudyKit.resetButton(label, fn, confirm)`。

## 先聽再做（鎖定互動面板）

互動場景一進來，面板被一層磨砂鎖蓋住且 iframe 設為 `inert`（滑鼠、觸控與鍵盤都進不去），上面寫著「按『開始學習』跟著老師操作」，開始後改成「先聽老師說明」。解鎖條件（只要一個成立，且解鎖後本次課堂不再上鎖）：老師說到要動手的句子或做出 `widget_highlight`／標示、本節講解結束、沒有講解可等、學生按「先自己試試」，或這個模組先前已經有存檔進度。實作在 `lib/study-classroom/lock.ts`，卡片 `StudyPanelLock`，鎖由講解列依 `needsOperation` 與操作提示決定。

## 題目只放在先測、檢核或互動模組

投影片只講解。要學生作答的題目（選擇題、練習題、「想一想」之類要回答的提問、(A)(B)(C) 選項）不可以放在投影片裡，只能放在三個地方：「先測：章名」測驗場景（前測）、「檢核：章名」測驗場景（中測／覆核），或互動模組裡的 `<sk-*>` 題型。規則文字是 `SLIDE_QUESTION_RULE`（`src/shared/module-kit-guide.ts`），會出現在：生成需求、官方「大綱」「投影片內容」「投影片動作」三個提示、`get_openmaic_guide`、`get_module_kit`、MCP 指引。

強制檢查：`check_openmaic_slides`（`GET /api/openmaic/generations/:id/slide-check`）掃描課堂所有投影片，找出放了題目的場景並說明原因；`publish_openmaic_classroom` 發布前同樣檢查，投影片有題目回 422，不能發布。判斷（`src/shared/slide-questions.ts`）：有 (A)(B)(C) 選項且在提問或留空、標示為「練習題／小測驗／選擇題」等、有題號（Q1／第 1 題）、或出現「請選出／下列何者／你的答案」加問號。已附解答的例題、用 A. B. C. 列的主題清單、修辭式標題都不算。

## 在頁面上寫字

講解列的「寫字」按鈕（投影片與互動模組）打開筆：筆、螢光筆、橡皮擦（按筆畫擦）、黑紅藍綠黃五色、復原、清除（要按兩次）、完成；Esc 放下筆，Ctrl/⌘+Z 復原。寫字時頁面不會被點到，放下筆後恢復操作。手機上第二根手指會捲動頁面（投影片閱讀器是捲動的，筆跡貼著文字、跟著捲動）；用手寫筆寫時，手掌碰到的觸控會被忽略。

筆跡以頁面寬度的千分比儲存，所以換螢幕大小仍然在同一段文字旁邊；每一頁分開存（存在進度存檔裡，鍵為 `ink:<場景 id>`，每頁最多 40 KB，最近 40 頁），下次回到這一頁會還原，換裝置也在。過多時先丟最舊的筆畫。測驗頁不提供（有自己的作答框）。實作：`StudyInk.tsx`（畫布）、`StudyInkBar.tsx`（工具列）、`lib/study-classroom/ink.ts`（筆畫、儲存、橡皮擦）。

## 手機「提問與討論」

手機上的提問與討論是底部面板，現在是一個聊天視窗：

- **完整對話**：上方是可捲動的對話紀錄（這一頁所有的提問與討論，老師、虛擬同學與你自己的發言依序排列，分段標題標出「提問」與「討論：主題」，進行中的討論會標示）。新訊息出現時，只有在你停在最下面時才會自動捲到底；往上翻回頭看時不會被拉走，右下會出現「新訊息」按鈕。回覆進行中會有輸入中的小點。
- **先看課程，隨時回來**：標題列的「先看課程」（沒有討論進行時是「收起」）、點面板外的暗處，都只是把面板收起來，討論本身繼續保留，不會被結束。收起時，講解列上方浮出一顆「回到討論」膠囊（顯示「大家正在發言」或「等你加入」，以及離開期間的新訊息數）；講解列的主按鈕在討論進行時也變成「回到討論」，「提問與討論」按鈕同樣能回來。回來之後輸入框、快速回覆都在，可以繼續發言。
- 面板標題列顯示「發言中」或「輪到你」。
- 討論進行時，主課程的「繼續」仍然暫停（討論結束或結束討論後才繼續），但可以隨時收起面板閱讀投影片與互動模組。

實作：`StudyDiscussionLog`（對話紀錄）、`lib/study-classroom/discussion.ts`（收起狀態與未讀數）、講解列的膠囊，以及 `patch-classroom.mjs` 中對 `PlaybackChromeRoot` 的補丁。對話內容讀自舞台 store 的 `chats`，不改動 Core 的 session 狀態。

## 進度存檔

- **上次看到哪一頁**：教室頁會把目前場景存到 STUDY（`PUT /api/openmaic/live/progress`，用課堂 session 辨識使用者與課堂），下次開啟時回到那一頁並提示「已回到上次的進度」。只有在還停在第一頁時才跳，所以學生手動選的頁不會被蓋掉。伺服器失敗時退回 `localStorage`。
- **互動模組內的進度**：kit 頁開啟時向播放器送 `{source:"study-kit-state", ready:true}`，播放器回傳存檔的 `STUDY_KIT_RESTORE`；之後每次操作 0.8 秒後把快照（`{v: 控制項值, c: 各元件狀態}`）送回播放器存檔。快照內容：滑桿、分段、開關、旋鈕的值；已答對的題目（還原成已答對的樣子，不重送 `answer` 事件）；`sk-steps` 與 `sk-tabs` 的頁；`sk-reveal` 是否展開；`sk-hints` 已看幾則；配平題的係數；`sk-record` 的數值紀錄與當時的檢核狀態。紀錄還原會限制在 `max-rows` 內、拒絕非有限數字並重新檢查合理範圍，不重送答題或步驟訊號。
- 紀錄欄位的名稱、單位、合理範圍或手動讀值容許差更新後，不會把舊數據套進新教材；模組會提示重新記錄。
- 沒有存的：答到一半的輸入、虛擬器材的桌面與讀值。每個模組最多 12 KB，一個課堂最多保留最近 40 個模組。表在 `0018_classroom_progress.sql`。

## 鍵盤

在電腦上，**空白鍵**繼續講解（等同點「繼續」）。只有按鍵沒有被別的東西使用時才算：輸入框、按鈕、連結、滑桿、單選與核取方塊、分頁、對話框都保留自己的空白鍵。互動模組在 iframe 裡，播放器看不到裡面的按鍵，所以 kit 會把沒有人使用的空白鍵用 `{source:"study-kit-key"}` 傳上來，播放器只接受自己 iframe 的訊息。Core 自己的空白鍵處理（`PlaybackChromeRoot` 的 keydown）也改成同一個 `handleStudyContinue`：課文還沒結束就讀下一句，課文結束、或測驗已批改，就前往下一章（走自適應路由）。官方版本在課文結束時按空白鍵會重播這一節，與播放器的「下一節」搶同一個按鍵。

**聚光燈的目標在看不到的地方**（例如答案在另一個分頁、面板還沒展開）：目標沒有版面尺寸時，kit 不畫暗幕、雷射與提示，等目標出現才顯示；目標占畫面六成以上時只畫外框，不再把整個模組壓暗（先前會把整頁蓋黑，只留右下角一塊亮區）。


## 動態

控制回饋 160ms、指令轉換 260ms、教材揭露 460ms、場景切換 380ms，交錯最多 160ms，曲線 `cubic-bezier(.22,1,.36,1)`。按壓：按鈕縮到 0.97、卡片與選項縮到 0.99；分頁的指示塊會滑動到選取項。事件依序連動：控制項 → 圖形與數值 → 教材區塊 → 進度。拖曳時圖形連續變化。偏好減少動態時所有動畫縮到 1ms。

## 元件

`sk-module`、`sk-split`、`sk-stack`、`sk-controls`、`sk-slider`、`sk-segmented`、`sk-toggle`、`sk-readout`、`sk-figure`、`sk-plot`、`sk-record`（搭配 `sk-col`）、`sk-steps`、`sk-reveal`、`sk-hints`、`sk-choice`、`sk-numeric`、`sk-order`、`sk-match`、`sk-callout`、`sk-progress`、`sk-observe`。屬性見 `get_module_kit` 的表格。老師的 `SET_WIDGET_STATE`、`HIGHLIGHT_ELEMENT`、`ANNOTATE_ELEMENT`、`REVEAL_ELEMENT` 由 kit 統一處理，模組不用再寫 message 監聽。

## 回饋邏輯（chatbot 必須寫）

| 要寫什麼 | 路由得到什麼 |
|---|---|
| 錯誤選項的 `misconception` 與 `feedback`；數值題的 `sk-wrong` | 學生答錯時，是哪個迷思 |
| `sk-observe`（器材操作至少一個 evidence）與 `StudyKit.emit('observe', …)`（操作迷思） | 學生操作器材時展現了理解或暴露迷思 |
| `sk-record` 的 `sk-col`（low、high、misconception） | 每筆紀錄是否合理，不合理時是哪個迷思 |
| `sk-hints` 或 `sk-reveal` | 提示與詳解用了幾次 |
| `sk-choice` 或 `sk-numeric` 加 `sk-explain` | 即時檢核結果、重試次數 |

`summary` 事件另外帶總時間與操作次數。

事件對應：`answer` 與 `observe` → `question` 訊號（對錯加迷思 id）；`hint`、`retry`、`step` 一對一。單元的先測與檢核仍由測驗場景的標題決定，見下。

## 場景命名規則

DSL 沒有欄位可以標示章節角色，所以用標題文字：`先測：章名`、`檢核：章名`、`章名〔補強〕`、`章名〔精簡〕`、`章名〔延伸〕`。有這些標題的課程才會啟用自適應路由，其餘課程照原順序播放。一章的教學可以分成多張：後續場景標題用 `章名｜小節`（全形），依序放在 `章名` 之後、`檢核：章名` 之前，播放器會逐張播完才進檢核；補強與精簡版同樣用 `章名〔補強〕｜小節`、`章名〔精簡〕｜小節`。夾在教學與檢核之間的無標題場景也算這章的教學，放在兩章之間的無標題場景則走不到，大綱驗證會拒絕。測驗題 id 以 `__m_<迷思id>` 結尾可標示該題探測的迷思；在它之前加 `__d1`／`__d2`／`__d3` 標示難度（基礎／核心／難題），例如 `q4__d3__m_forgot-sign`。沒有難度標記的題目當作核心題。

## 前測與教學順序

`PRETEST_RULES` 與 `TEACH_FIRST_RULE`（`src/shared/module-kit-guide.ts`）是強制規則，會出現在 `get_module_kit`、`get_openmaic_guide`、課程需求（`/openmaic-core` 的 requirement）、MCP 說明，以及官方 `requirements-to-outlines`、`slide-content`、`slide-actions`、`quiz-content` 範本（`patch-classroom.mjs`）。

- **前測要精準看出程度**：基礎 1 到 2 題（先備知識）、核心 2 題（本章主要概念與公式）、難題 2 題（考試等級：多步驟、整合概念、單位或條件陷阱、陌生情境）。錯誤選項對應真實迷思並帶 `__m_`，不能靠猜測或題幹洩漏答案。沒有難題，路由無法分辨「真的會」與「只會簡單題」。
- **先講解，再實作**：公式、定義、符號、單位、定理、步驟與推理規則，都要先在講解場景交代（是什麼、為什麼、符號單位、適用條件、一個有完整解答的例題），之後才能出現在檢核、〔補強〕、復測與〔精簡〕難題裡；一次只引入一個新東西。例外：先測（本來就在教學前診斷）與互動模組（先動手探索、即時回饋）。
- 這些規則是給 chatbot 的提示，沒有程式檢查；唯一有檢查的仍是投影片不得放題目（`check_openmaic_slides`）。已發布的課程沒有難度標記，路由仍照原本的方式運作。

## 手機

- kit 在 700px 以下自動單欄：圖形與圖表置頂並固定，控制項標籤、滑桿與數值同一列，觸控目標至少 40px。`sk-tabs` 讓探索與每一題各佔一屏，分頁列固定在上方。我用瀏覽器在 375×560 與 375×480 量過：探索頁與每一題頁都不需要捲動，答錯後的回饋會自動捲入畫面（最多多捲約 26px）。
- 圖形要放在 `sk-split` 的直接子層（或其中的 `sk-stack`），手機上才會置頂。舊式自寫 HTML 模組不受影響，也不會得到這些版面。

## 瞄準

老師的聚光燈、雷射筆與標示動作在手機閱讀器上由 `lib/study-classroom/slide-aim.ts` 重新對應（見相容性清單的 Phone classroom）。互動模組裡由 kit 自己處理 `HIGHLIGHT_ELEMENT` 與 `ANNOTATE_ELEMENT`，不經過閱讀器。

## 限制

- 新題型在獨立頁面驗證過：分類、配對、排序、標示、填空、配平、旋鈕調數值的判分與回饋文字，以及真實滑鼠拖曳（分類、標示）。`sk-pick`、旋鈕（拖曳旋轉與方向鍵）、排序拖曳列用模擬的指標事件驗證過，沒有用真實觸控；手機寬度的版面只看過標示與分類。
- 虛擬器材與 `sk-record` 在獨立頁面用瀏覽器驗證過：滴定（終點 21.83 mL 一滴變色）、倒液、固體排開、天平、加熱與時間 ×10、pH 計與吸量管、彈簧（k=25 時 170 g 伸長 6.7 cm）、斜面光閘（加速度與理論值 0.69 m/s² 相符）、電路（6 V、6 Ω 燈泡電流 0.945 A）、光學桌、顯微鏡對焦。電路的拖曳旋鈕、光學桌與顯微鏡的真實拖曳、單擺的計次沒有逐項人工操作驗證。尚未用真實 chatbot 生成並在正式課堂播放過，也要重建部署 Core 後課堂才會注入新元件與新的播放器行為。
- 播放器的「換你操作」講解列、找虛擬同學討論按鈕、討論面板隱藏老師講解，是 Core 補丁：補丁錨點已在乾淨的 Core 上套用成功，但這些改動沒有在實際課堂跑過，也沒有對 Core 做型別檢查。
- 「復測」放在 `〔補強〕` 場景最後一頁，之後由播放器讓學生再做一次「檢核」；播放器本身沒有獨立的復測場景。
- 舊的 `start_course_generation`（mastery/v1）格式只更新了互動規則的提示，沒有補強、精簡與課後場景。
- 目前只在瀏覽器驗證過元件的外觀與行為（桌面與 375px）。尚未用真實 chatbot 生成並在正式課堂播放過。
- 官方模板仍要求 chatbot 輸出 `widget-config` 與 message 監聽；附加的指引要它改用元件庫，chatbot 是否照做要看實際生成結果。
- `sk-plot` 的函式由 chatbot 以 JS 提供，kit 不解析字串運算式，所以仍需要少量領域腳本。
- 注入後每個使用元件庫的頁面多約 29 KB（不佔 chatbot 的輸出 token）。

手機優先的完整規則（含投影片重排與測驗）見 MCP 的 `get_mobile_design_guide`；模組頁面需有 viewport meta 與寬度 `@media`，播放器才會用真實手機寬度顯示。
