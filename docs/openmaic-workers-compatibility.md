# OpenMAIC Workers compatibility inventory

Baseline: official OpenMAIC **1.3.0**, commit `fe2cf7dade345f4eaaf9afb1771e6734e17edaab`. This inventory compares that pinned source with STUDY's Workers adapters. It is a source audit, not a claim that every upstream feature has passed an end-to-end test. “Unavailable” below includes deliberate product choices; it does not imply Cloudflare could never support a replacement.

## Learner-only classroom

The classroom is for learning. STUDY serves only `/classroom/:id` from the Core; `/workspace`, `/workbench` and `/generation-preview` are not reachable. The classroom UI no longer shows the header (settings, language, theme, Pro/edit switch, export menu), cannot be put into edit mode, and has no speed, auto-play, volume or microphone controls. Core APIs used only by those screens (model and provider verification, skills, usage, export video, ComfyUI workflows, transcription, Azure voices, `generate-classroom`) are not proxied. Generation still runs through MCP and STUDY's own service binding, which does not use the public proxy.

## Phone classroom

On phones (the Core's own mobile query: width up to 767px, or short coarse-pointer landscape) slide scenes render in a reflowed one-column reader instead of the 1000px canvas: reading order by position, titles first, decoration and page numbers dropped, inline font, size and color replaced so text always fits, long words wrap, tables and formulas scroll inside their own card. Charts show a note instead of a chart. Spotlight, laser and highlight actions are re-aimed for the reader rather than the canvas: a target that became a block is aimed at directly, a dropped decoration aims at the block that sat on it (otherwise the nearest block), the reader scrolls the target into view when it is off screen, a spotlight dims the other blocks and lifts and rings the target, a percentage-region spotlight cuts out the matching part of the block, a laser is a red dot (the action's color, red by default) with a glowing core, a breathing bloom, two staggered ripples and a short trail: it pops in with a slight overshoot, glides to the next block when the aim moves, sits in the margin beside the first line of text (centered on images and tables), and fades out when the action ends, and a highlight rings the block without dimming. Dimness and timing come from the action; the engine's own auto-clear ends the effect. Reduced motion removes the scale, pulse and smooth scrolling. The dialogue dock becomes a rounded sheet with 44px targets and a floating explanation panel. All surfaces use the main app's tokens (soft, lift and glow shadows, the `#0a0a0a→#3f3f46` primary gradient with a top highlight, 16px and 24px radii, press scale .97, `cubic-bezier(.22,1,.36,1)`).

## Quizzes and loading

- **"I don't know"**: pretest, diagnostic and checkpoint scenes (titles starting 先測／前測／診斷／檢核) show an extra choice, `?`, on single and multiple choice questions. It is added by the player, not by the chatbot, and is exclusive in multiple choice. It grades as not correct, is not styled as a wrong answer in review, never becomes a misconception, and is recorded as an `unsure` signal (migration 0016) that makes the explanation detailed and marks the chapter for review. In-class quizzes do not get it.
- **Results at once**: the result of a quiz is shown the moment it is submitted. Grading is local and instant; saving the submission and the review now happens behind the result (one retry after 1.5 seconds), and Retry waits for the save.
- **Opening a classroom**: STUDY warms the classroom service (`POST /api/openmaic/warm` reads the stored lesson) while the learner reads the course page. Opening then runs on the course page behind a step list that reflects real progress (permission, resources, waking the service, reading the lesson, entering) with tips, and navigates only once the service has answered. If setting the session quietly fails it falls back to the old form post. The Core's own loading screen shows the same steps, a skeleton of the classroom and tips.
- **Speed**: the route request carries unsent signals (one round trip), the server reads in parallel, the next two slides' images are fetched while the current one is read, and lesson media may be kept by the browser for an hour (`private, max-age=3600`). Everything else stays `no-store`.
- **ASCII Core bundle (2026-11-02)**: the Core Worker is one ~64 MB module. Bundlers left raw Unicode in a few regex literals (date locales, text detection), and one non-Latin-1 character makes V8 hold the whole source as two-byte text (~128 MB), past the isolate memory limit. Cloudflare then dropped the isolate after every request, so each request, even `/api/study-mcp/status`, booted Next.js again: 1.5–3 s CPU and 3.4–7.7 s from Taiwan, with a classroom open making many such requests. A/B on Cloudflare with the same bundle: escaped to ASCII, warm requests use 11–33 ms CPU and take 240–340 ms. `build` now escapes the server bundle (`cloudflare/scripts/ascii-bundle.mjs`), dry-runs the Core Worker, fails if the output is not ASCII, and records `asciiBundle: true`, which the deploy workflow requires.
- **Keep warm**: the scheduler cron runs every minute (was every five). Its tick reaches the Core and the PGlite database Durable Object, which Cloudflare evicts after a couple of idle minutes, so a learner's first open does not pay the database boot.
- **Phone ask-and-discuss**: a bottom sheet (grabber, close button, 44px targets, 16px inputs so iOS does not zoom) that hides the teacher and participant columns. The text box stays open (the avatar column that toggled it is hidden), answers are not dimmed or capped at 110px, and the sheet rides above the on-screen keyboard. The patch applies to the pinned roundtable source and the layout rules are tested, but it has not been operated on a real phone; see limitations.

## Upstream options not enabled here

These are **not proven Worker incompatibilities**. Several are off by default in the original release too:

- Editable PPTX import UI: the parser Worker is ported, but the upstream import flag is not enabled. Upstream's own editable-import size/slide limits still apply.
- Vocational task engine and its specialized renderer.
- Experimental Pi native child runtime and native child spotlight.
- Experimental courseware element-reference UI and associated experimental renderers.
- MP4 menu: disabled here for the concrete missing render-service dependency described above.

## Features retained, rather than established losses

The full official generation/compiler/editor packages are built; Workers is not a replacement lesson-module engine. Durable generation coordination, MCP task replay, owner-scoped course persistence, materials/knowledge-base records, browser slides, interactive HTML/3D/games/programming content, formula rendering, whiteboard actions, native Pi tool loops, choice quizzes, classroom editing and saved learner runtime remain in the source/runtime architecture. Specific content can still fail and needs its own validation.

PPTX export, offline HTML export, classroom ZIP import/export, knowledge-base folder/search flows, custom user skills and PBL screens are not classified as incompatible merely because they were not exercised by the classroom smoke test. Their complete end-to-end parity is **not yet established**. Offline exports do not carry the server-side live API key or grant unrestricted offline AI access.

## Live model configuration and security

Open **Admin → 課堂 AI**. Choose an OpenRouter text model supporting tool calls, enter its key, set limits, enable the service and explicitly enable the relevant users. API keys are AES-256-GCM encrypted in D1 with a separate Worker secret. Reads return only a configured/not-configured flag. Core receives a short-lived, owner/classroom-bound, domain-separated signed grant; it never receives the OpenRouter key. Requests go only to the fixed OpenRouter endpoint. Missing, unreadable or disabled credentials automatically disable live discussion, questions, PBL interaction and AI review, including while availability is being checked. Saved teaching and system grading continue. Client state refreshes on focus and periodically; every server call rechecks policy. No mock reply or MCP fallback is used for these live features.

Daily quotas reset at UTC midnight (08:00 Taiwan). Atomic D1 admission prevents parallel requests from overspending the same application quota. Each model call reserves a conservative token allowance before sending and settles against provider usage when known. Failed/unknown-usage calls keep their reservation. A turn can contain several native agent/tool calls. Application token budgets are not an exact dollar cap; set an additional credit limit on the OpenRouter key when needed. Provider errors are sanitized and requests are not automatically retried.

OpenRouter's `provider.data_collection: "deny"` restricts routing to providers that satisfy its data-collection policy; it is not a blanket claim of zero retention. See [OpenRouter provider selection](https://github.com/OpenRouterTeam/docs/blob/main/guides/routing/provider-selection.mdx).

## Phone slide reader and aiming

The phone reader (`StudySlideReader`) is a one-column layout: a title with an accent rule, roomy 16.5px text cards with styled list markers, figures that open full screen on tap (pinch to zoom), tables with scroll-edge shadows, safe-area padding. Spotlight, laser and highlight actions used to disappear after `EFFECT_AUTO_CLEAR_MS` (5 s), long before a phone learner, who reads at their own pace and has to scroll to the target, got there. The patch now holds them for ten minutes and `advanceNarration` clears them when the learner finishes the line. The spotlight dims everything else more strongly, and when the aimed block is off screen a sticky pill ("老師正在說明這…") scrolls back to it.
