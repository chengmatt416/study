# 自適應課堂路由

目標：依先測、隨堂測驗、即時提問與模組操作，調整接下來播放哪些內容與解說詳細程度，並把模型成本壓到最低。邊界見 [ai-boundary.md](ai-boundary.md)。

## 原則

教材全部由 MCP chatbot 預先生成，包含每章的多個版本。執行時只**選擇**版本，不生成文字。選擇分三層，越貴越少用：

| 層 | 誰決定 | 成本 |
|---|---|---|
| 0 規則路由 | `src/shared/adaptive-learning.ts` 的純函式 | 免費，隨時可用，也是其他層失敗時的備案 |
| 1 弱點 MCP | chatbot 呼叫 `get_learner_weaknesses`，在使用者自己的訂閱內補強教材 | 平台零成本，非即時 |
| 2 模型路由 | 學生本次課堂手動啟用 AI 後，OpenRouter 在決策點輸出結構化 JSON | 有配額，一次只送精簡摘要 |

## 學習者訊號

由課堂送到 `POST /openmaic/live/signals`（需課堂 session cookie），存入 `learner_signals`，每位學習者每間課堂最多保留 2000 筆，每分鐘最多 300 筆。

| kind | 意義 |
|---|---|
| `pretest` | 先測單題。`correct`，答錯時可帶 `misconception`；`difficulty`（1 基礎、2 核心、3 難題）取自題目 id 的 `__d1`／`__d2`／`__d3` |
| `checkpoint` | 一次章節檢核。`correct` 代表整次是否全對 |
| `question` | 隨堂測驗單題（答錯才送），同樣可帶 `difficulty` |
| `unsure` | 學生選「我不會」。難題（`difficulty: 3`）的「我不會」另計 `unsure_hard`，不算弱點 |
| `hint` | 點「不懂，拆開說明」 |
| `retry` | 重做互動步驟 |
| `ask` | 向 AI 提問 |
| `step` | 完成一個互動步驟，`value` 可放耗時毫秒 |
| `module` | 互動模組的總結：`value` 為總耗時毫秒，`ops` 為學生操作過的控制項數（來自模組的 `summary` 事件） |
| `skip` | 學生申請跳過章節（伺服器依 `/route` 的 `skip_request` 寫入，課堂不能直接送） |
| `skipped` | 路由判斷「同意跳過」後由伺服器寫入，之後不再排回該章（課堂不能直接送） |

訊號只記 id、對錯、計數，不存學生作答文字。`concept` 是章節 id，由課堂提供，伺服器無法對照教材驗證；訊號限定在該使用者與該課堂內，所以偽造只影響自己的路由。

**先測看難度**：`readiness` 依各難度的答對情況判斷：`foundation_gap`（基礎題答錯）、`core_gap`（基礎對、核心錯）、`hard_gap`（基礎與核心都對，只錯難題）、`core_ready`（全對但沒有難題可證明）、`ready`（全對且含難題）。沒有難度標記的課程，答錯一律當核心錯、全對當 `ready`，行為和以前相同。`hard_gap` 的學生不是弱，看標準教學並加強難題，不會被送去〔補強〕，也不會被當成可以〔精簡〕。`difficulty` 由 migration `0019_signal_difficulty.sql` 加到 `learner_signals`（要在部署 Worker 前套用）。

掌握度：`mastered`（先測全對且含難題、沒答錯題，或檢核通過且失敗少於 2 次）、`shaky`（先測基礎或核心答錯、檢核失敗、提示 3 次以上、重試 3 次以上、答錯 2 題以上，或同一迷思出現 2 次）、其餘 `unknown`。

## 檢核失敗與模組操作

- **檢核失敗一定進補強**：`trigger` 為 `checkpoint` 且該章檢核尚未通過時，不論規則或模型，下一步固定是**同一章**的〔補強〕（沒有補強版就是同一章標準版，解說放慢）。不會送去別的章節，模型選了別的也會被伺服器改回。檢核通過才進下一個未完成的章節。
- **模組操作交給路由模型**：模型摘要每章附 `module_use`（互動步驟數與平均每步秒數、完成的模組數、總秒數、操作過的控制項數），最近動作也帶每步／每個模組的秒數與控制項數。步驟太快、操作很少代表在亂點（詳細解說，不給精簡）；每步很久、提示或重試多代表吃力（詳細解說並把碰到的迷思放進 `focus`）；快又準代表可以精簡。模組操作只影響 `detail`、`focus` 與章節順序，**不會**造成補強。

## 學生申請跳過章節

課堂講解列的「跳過本章」送出 `POST /openmaic/live/route`（`skip_request: 章節 id`，章節附 `checkpoint: true|false`）。學生只是「申請」，由路由決定：

| 決定 | 條件 | 結果 |
|---|---|---|
| 同意 | 該章已掌握（`mastered`） | `decision.skip` 含該章、`next` 為下一個未完成章節；伺服器記下 `skipped` |
| 挑戰 | 未證明掌握，但該章有檢核 | `decision.challenge: true`、`next` 為該章：直接進檢核；通過即完成，沒通過進補強 |
| 拒絕 | 該章沒有檢核，或模型判斷有明顯缺口 | 照常播放該章 |

規則路由用上表預設；學生啟用 AI 時由模型在這三者之間選，伺服器擋掉沒有掌握證據的「同意」（改為挑戰或照常教）。

## 路由決定

```json
{"next": "章節 id 或 null", "variant": "standard|remedial|quick|enrich", "detail": "brief|standard|detailed", "skip": ["章節 id"], "focus": ["迷思 id"], "challenge": true}
```

- `challenge` 只在學生申請跳過時出現：直接進該章的檢核測試。
- `next: null` 代表所有章節完成，進最終遷移檢核。
- `variant` 只能是該章實際擁有的版本，否則一律改成 `standard`。**`remedial`（補強）只在該章「檢核」答錯且尚未通過時使用**；先測答錯、隨堂測驗答錯、提示、重試、提問或「我不會」都不會送去補強，只會讓 `detail` 變成 `detailed`（解說放慢、展開）。模型就算選了 `remedial`，伺服器也會在沒有檢核失敗時改回 `standard`。
- `detail` 是解說詳盡程度：`brief` 用精簡版，`detailed` 展開 `explanation_md` 並放慢步驟。
- `skip` 只收已掌握且**沒有 `quick` 版本**的章節；規則路由只跳過最前面連續的這類章節。已掌握且有 `quick` 版本的章節不會被跳過，改播放 `quick`（章名〔精簡〕：不講解，只放考試陷阱提醒與難題練習＋解析），之後仍進檢核。
- `focus` 只能是該章已出現過的迷思，最多 3 個，用來優先播放對應補強步驟。

`POST /openmaic/live/route`（body：`chapters:[{id,title?,variants}]`、`current`、`trigger`）永遠先算規則決定。只有 AI 可用且學生本次已啟用時才呼叫模型。模型輸出經伺服器驗證，無效就用規則決定並回報 `reason`。回應固定為 `{decision, source: "model"|"rules", reason?}`，所以模型停用、超額或出錯時學習不中斷。`reason` 可能是 `ai_unavailable`、`session_not_enabled`、`invalid_model_output`、`minute_limit`、`daily_limit`、`token_or_turn_limit`、`provider_unavailable`。

模型收到的摘要含章節 id 與章名（讓它知道每章教什麼）、可用版本；學生碰過的章節另附：掌握度、`readiness`、先測各難度答對比（例如 `{"foundation":"2/2","core":"1/2","hard":"0/2"}`）、檢核次數、提示／重試／提問／「我不會」次數、迷思 id；以及目前章節最近 8 筆動作（種類、對錯、難度、迷思，由舊到新）。沒碰過的章節只有 id、章名與版本，所以 40 章也維持在約一兩千 token；不含教材、學生作答文字、姓名或 email。系統提示說明各種 `readiness` 該怎麼選（基礎或核心缺口 → 標準教學並詳細解說；只錯難題 → 標準教學；證明熟練 → 精簡；檢核失敗才補強）。伺服器另外擋掉違反證據的選擇：只有 `mastered` 的章節才能選 `quick`，只有檢核失敗未通過的章節才能選 `remedial`，否則改成 `standard`。建議課堂只在決策點呼叫：先測結束、檢核結束、提問後、互動步驟間隔，不要每次點擊都呼叫。

## 啟用與配額

- 學生要用任何 AI（`interaction`、`regrade`、`route`）都須先在該課堂啟用：`PUT /openmaic/live/session {enabled}`。啟用持續 4 小時，可隨時關閉，只對該課堂有效。預設是關閉。
- 啟用還需要：管理員已開啟全站課堂 AI 並設定 key、使用者群組有 `ai` 功能、管理員沒有對該使用者停用。
- 管理員用每分鐘、每日、全域 token 配額限制花費。逐人名單改為預設允許，管理員仍可對個人停用或調整配額。
- 規則路由與訊號紀錄不需要啟用，也不消耗配額。

## 弱點 MCP

`get_learner_weaknesses({classroom_id?, limit?})`，唯讀，需要 `study:read`。回傳呼叫者自己近 90 天內仍未掌握或有迷思紀錄的章節，附課堂連結。chatbot 依此為迷思生成補強教材，不重做整門課。

## 課堂播放器接線

已接上（`integrations/openmaic/cloudflare`）：

- `src/shared/course-map.ts`（Core 建置時複製成 `lib/study-classroom/course-map.ts`，overlay 內同名檔只是轉出口）依場景標題判讀章節、先測、檢核與補強／精簡／延伸版，也判斷每章的教學由哪些場景組成：播放器按順序走完才進檢核，路由只在章與章之間決定。標題規則見 [module-kit.md](module-kit.md)。沒有這些標題的課程完全不受影響。
- `lib/study-classroom/adaptive.ts` 收集訊號（測驗結果、點「不懂這一步」、課堂提問、互動模組回報），批次送到 `/openmaic/live/signals`；按「繼續」時在決策點呼叫 `/route` 並開啟指定版本。章節沒有檢核場景時，看完教學即視為完成。
- 先測與檢核場景由系統批改後送出訊號；答錯時用題目 id 後綴 `__m_<迷思id>` 判斷迷思。
- 解說詳盡程度：`detailed` 會自動展開完整說明，`brief` 與 `standard` 維持原樣；畫面會說明目前是依表現調整。
- 課堂工具列有「啟用本次 AI」按鈕（AI 可用時顯示），對應 `PUT /openmaic/live/session`。
- 互動模組用元件庫生成，回饋事件經 `installStudyKitBridge` 進入同一條訊號流程。

仍未完成或未驗證：

1. 以上播放器修改只通過 patch 錨點檢查、Core 型別檢查與單元測試，尚未在實際課堂中瀏覽器驗證，也沒有重建部署 Core。
2. 沒有用真實 chatbot 生成過帶這些標題與標籤的課程，所以 chatbot 實際遵守程度未知；官方生成管線是否原樣保留測驗題 id 也未驗證。
3. 先測沒有「全部先測放最前面」的強制檢查；若 chatbot 把先測散在各章，第一次路由的時機會不同。
4. 檢核答錯後重學再回到檢核場景，是否能重新作答取決於官方測驗元件對已提交作答的處理，尚未確認。
5. 互動步驟（`step`、`retry`）只來自元件庫模組；舊式自寫 HTML 模組不會回報。
6. 官方課堂本身沒有先測畫面；先測是普通 quiz 場景。

## 學習流程的保護措施

- **路由不讓學生等**：模型路由最多等 6 秒、最多要 1024 token，超時就用免費規則；主要的決策點（先測與檢核交卷後）會在背景先算好，學生按「繼續」時通常已有答案。
- **路由失敗不會亂跳**：退回線性順序時，會跳過沒被選中的補強、精簡、延伸版本。
- **提示只跟著它的場景**：路由說明（改看補強版、檢核未通過、再挑戰一次）只顯示在目標場景，手動跳章後不會殘留。
- **完成後的總結**：全部章節完成時顯示掌握幾章，以及建議再複習的章節。
- **檢核沒過**：回到檢核場景時提示按「重試」重新作答（官方測驗元件的重試按鈕）。
- 手機上「詳細」模式不會自動展開浮動說明面板，避免蓋住簡報；空白簡報頁會顯示說明。

## 先測一章一章做（2026-11-16）

以前所有章節的先測排在課程最前面，學生要先答完全部（12 章就是 60 到 72 題）才看到第一頁講解。場景順序沒有改（先測仍集中在最前面，chatbot 的規則不變），改的是播放順序：

- 每個先測答完都會請路由決定下一步（`routeStep`），所以第一章的先測之後直接進第一章，不會接著考第二章的先測。
- 路由回應多一個 `pretested`：下一章還沒被探測過（沒有先測作答、沒選過「我不會」、沒做過檢核、沒被跳過）時是 `false`。播放器看到 `false` 且那一章有先測場景，就先開那一章的先測（`applyDecision`），答完再依結果進標準版或〔精簡〕版。
- 先測沒作答就按繼續，不會被困在先測：同一個先測不會開第二次，直接進講解。
- 申請跳過章節（challenge）照舊直接進檢核。
- 伺服器還沒回報 `pretested`（舊版 STUDY）時，播放器維持原本「先測連著考」的順序（`keepPretestOrder`），不會讓後面的先測永遠沒被考到。所以部署順序不拘。
- 路由請求失敗時播放器照場景順序往下，也就是回到舊的行為。

代價：每個先測之後多一次路由請求。規則路由不花錢；學生啟用課堂 AI 時，每章的先測會各用一次路由模型呼叫（以前是全部先測之後一次），仍受原本的配額限制。

程式在 `src/shared/course-map.ts`、`src/shared/adaptive-learning.ts`（`isPretested`）、`src/worker/routes/live-ai.ts` 與課堂的 `adaptive.ts`。

## 學習教練（2026-11-17）

教練看學生在課堂裡一再弄錯的地方，解釋那一個觀念，並建議接下來怎麼走。分成兩層：

**觀察與路由建議（規則，免費，一律開啟）**。`src/shared/learning-coach.ts` 的 `coachFocus` 讀已記錄的學習訊號，在學生目前的章節找出卡住的地方，依序是：

1. 同一個迷思出現 2 次（`misconception`）。再多錯 2 次（共 4 次）是第二層：不再解釋，請學生回去看講解。
2. 檢核沒通過（`checkpoint`）；第二次沒通過是第二層。
3. 沒有特定迷思但卡得久（`struggle`）：答錯 3 題、提示 4 次、重試 4 次或選「我不會」2 次。

`coachRoute` 決定建議：檢核沒通過 → 〔補強〕版（章節沒有補強版就回去看講解）；錯 3 次以上、第二層或 `struggle` → 回去看這章的講解；否則繼續。先測的作答不算卡住（還沒教），課堂不會因為先測去問教練。

**解釋（一次模型呼叫，要學生開啟課堂 AI）**。`POST /api/openmaic/live/coach` 把章節名稱、卡住的迷思與次數、作答統計、最近 12 筆訊號，以及課堂送來的該章標準講解文字（最多 6,000 字）交給模型，回傳一句重點（最多 24 字）、兩到四句解釋、一個讓學生自己檢查的問題，以及建議路徑（只能是該章真的有的選項）。模型只能用講解文字裡教過的內容解釋；講解文字被當成資料，不依其中的指示行事。

費用控制：

- 課堂端只在跨過門檻時才問伺服器，每種情形問一次（`coach.ts` 的 `coachShouldAsk`），而且等 2.5 秒，讓學生先看完題目自己的回饋。
- 同一個學生、同一堂課、同一個卡住的地方只呼叫一次模型，結果存在 `classroom_coach_notes`；重開課堂讀回同一則，關掉後不再出現。
- 模型回覆不能用時存規則版，不重試。第二層一律用規則。
- 每堂課每天最多 6 則模型解釋，超過改用規則版。另外受課堂 AI 原本的每分鐘、每日與 token 配額限制。
- 沒開課堂 AI、沒有 key 或配額用完：回規則版（指出重複的錯誤與建議路徑，不解釋觀念，也不存檔），並提示開啟課堂 AI 可以得到解釋。學生之後開啟 AI，同一個錯誤再出現時會再問一次。

**課堂裡的樣子**（`StudyCoach.tsx`，掛在講解列上方）：一張卡片，最上方顯示重點，下面是解釋與「想一想」；按鈕是「回去看這段講解」／「看補強版」與「先繼續作答」。要不要照建議走由學生決定，不會自動跳頁。照建議回去時記一次提示訊號；從〔精簡〕或〔補強〕頁回去看講解，看完會回到原來那一頁（沿用精簡版的返回機制）。章節之間的路由仍由原本的規則／模型路由決定，教練的提示與學生之後的作答都會進到同一份訊號裡。

## 作答回饋

- **作答的批註**：互動模組回報作答時，講解列上方會顯示一句短評（「答對了！」「修正得好！」「再想想」），檢核通過與整頁完成也有；連續作答只顯示一句，不會疊在一起，也不擋住點擊。先測不顯示（先測不給回饋）。
- **模組裡的勾與叉**：元件庫的回饋框把 ✓／✗ 改成一筆畫出的勾、兩筆畫出的叉（沙盒裡不能讀字型，所以這裡只畫記號）。
